# AI 参会者与全程上下文

AI 持续理解讨论，并在有价值时补充观点、追问或提出异议；没有新贡献时继续倾听。场景和已有会议背景、参会角色决定关注重点，不增加个人辅助目标输入。

## 上下文来源

每项分析都使用共享的 `prepareAnalysisContext`。桌面 Codex 保留合并的阶段／共识调用，其上下文准备与 Web API 相同。

- 短会议直接传入完整有效原话。
- 序列化原话超过 18,000 字符后，按约 6,000 字符一段整理较早的定稿转写，保留后续原文。中间的未定稿不会挡住它之后的定稿。字符阈值是应用预算，不是模型 token 上限。
- 每段记忆记录讨论、提议、确认、异议、解决、否决或撤销事件，以及原话 ID、时间范围和源内容摘要值。
- 记忆是历史事件，不代表所有条目仍有效。分析需要按时间核对后续修改，保留未被撤销的早期约束。
- 每次复用记忆前校验原话 ID、文本、说话人、时间和定稿状态。删除、修正、插入或换会议后，从失效处重新整理；删除操作同时清除当前派生分析，避免继续使用旧观点。
- 当前 90 秒／3 分钟窗口只是注意力重点，完整记录仍在上下文中。问答另外从全部转写查找匹配原话及相邻发言；相关度相同时优先较新的发言。固定片段不受旧的 24 条上限影响。

某一段整理失败时保留已经完成的记忆，其余内容继续用原话。全程记忆与剩余原话合计超过 100,000 字符时明确报错，并带回已完成的记忆，不偷偷只取最近窗口，也不改用模拟分析。大量历史首次整理会增加等待时间。真实模型对摘要完整性、状态变更和建议质量的判断需要进一步用真实会议验证。

## 参会观点与事实分离

实时结果包含 `participantView`：当前理解、补充／追问／异议／倾听意图、发言候选、原因和原话出处。上一轮观点独立传给下一轮，用于检查理解变化和避免重复，不作为会议事实。

AI 输出只有在后续真实转写中被讨论或确认后，才能成为团队决定。模型引用不存在的原话 ID 时，丢掉这些引用并继续本次分析；引用存在不等于语义判断已经被证明，用户可展开核对。

发言建议增加“倾听观察”。此时三种时长的脚本为空，实时与回放界面均显示倾听原因。

各场景的关注维度与规则位于 `shared/meeting/scenarios/assistance.ts`，现有场景配置继续负责阶段、角色和纪要语言。头脑风暴发散期允许没有共识；评审关注证据与通过条件；同步会关注阻塞、依赖、责任和时间。

## 保存与兼容

会话新增可选 `meetingMemory`、`questionContext`、`roleContext` 字段；原存储键和已有字段不变。记忆只在会话顶层保存一份，回放快照保存当时的参会观点与关注点，避免每轮复制全部记忆。老会话无需迁移。

开始新会议时清空记忆并使所有在途分析结果失效。语音和文本仍走各自已配置的服务；没有增加云端会话同步或 AI 自动播音。

## 验证

`tests/meetingContext.test.ts` 覆盖上下文覆盖、增量复用、转写修订、跨会话隔离、历史证据查找、各分析任务的上下文、场景差异、参会观点与倾听、存储兼容和输入校验。

`tests/meetingContextStore.test.ts` 验证全程问答、上一轮 AI 观点的独立传递、记忆只保存一次，以及新会议忽略迟到结果。测试使用受控模型响应，不代表真实模型效果评测。
